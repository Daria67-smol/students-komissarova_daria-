`**Магазин - заказы в терминале**`

Небольшой интернет‑магазин: каталог товаров, корзина, заказы, остатки, корзина, тесты.

**`Функциональные требования`**
1.	Каталог — список товаров: артикул, название, категория, цена, остаток на складе. Фильтр по категории.
2.	Поиск — по подстроке в названии, без учёта регистра.
3.	Карточка товара — подробная информация, включая тип товара и его особенности (например, «цена за кг» или «цифровой, доставка на email»).
4.	Корзина — добавить товар с количеством, изменить количество, убрать товар, показать корзину: позиции, количество, сумма по каждой строке, сумма без скидки, скидка, итог к оплате. Повторное добавление того же товара увеличивает количество, а не создаёт вторую строку.
5.	Промокод — к корзине применяется один промокод (новый заменяет старый). Промокоды разных типов считают скидку по-разному (п. 4). Неизвестный промокод или промокод, условия которого не выполнены (например, сумма меньше порога), — понятное сообщение.
6.	Оформление заказа — проверка остатков по всем позициям, списание остатков со склада, создание заказа (номер, позиции, сумма, скидка, итог, статус new), очистка корзины. Если хотя бы одной позиции не хватает — заказ не создаётся и склад не меняется вообще (никаких «частично списали»).
7.	История заказов — список заказов (номер, количество позиций, итог, статус) и просмотр конкретного заказа.
8.	Отмена заказа — статус меняется на cancelled, остатки возвращаются на склад. Отменить уже отменённый заказ нельзя.
9.	Приход товара — увеличение остатка товара (команда «администратора», без авторизации).
10.	Экспорт — выгрузка всех заказов в CSV (одна строка — один заказ: номер, статус, количество позиций, сумма, скидка, итог).
11.	Журнал действий — значимые действия (добавление в корзину, применение промокода, оформление, отмена) пишутся в текстовый лог data/shop.log с помощью декоратора (см. п. 5).
12.	Обработка ошибок — несуществующий артикул, количество ≤ 0 или не числом, нехватка остатка, неверный промокод, оформление пустой корзины, отсутствующий или повреждённый JSON — понятное сообщение, а не traceback.

**`Требования к товарам и скидкам`**

1. Типы товаров (минимум 3)
Каждый тип должен реально отличаться поведением, а не только полем type:
•	Штучный (piece) — количество только целое, не больше остатка.
•	Весовой (weight) — цена указана за 1 кг, количество — дробное число килограммов (например, 0.35), есть минимальный вес (например, 0.1 кг); сумма строки округляется до копеек.
•	Цифровой (digital) — склада нет (остаток не проверяется и не списывается), в корзине может быть максимум 1 штука.

2. Типы промокодов (минимум 3)
•	Процентная скидка — например, SALE10: −10% от суммы корзины.
•	Фиксированная скидка от порога — например, MINUS500: −500 ₽, если сумма корзины не меньше 3000 ₽. Скидка не может сделать итог отрицательным.
•	«3 по цене 2» или скидка на категорию — например, COFFEE3: каждый третий штучный товар категории coffee бесплатно; или TEA15: −15% только на товары категории tea.

3. Минимум данных
•	Не менее 10 товаров в каталоге, не менее 3 категорий.
•	Все три типа товаров представлены в каталоге.
•	Не менее 3 промокодов разных типов в конфиге.
